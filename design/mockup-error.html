三种读不到数据的情况

同一个错误组件，三种参数。每种都给出确切原因、可复制的技术信息，和下一步能做的事——不说"出错了，请重试"。

病例 A · 仓库不存在 HTTP 404

查无此仓

NOT FOUND

GitHub 说这个地址上没有仓库。两种可能：名字拼错了，或者它是私有仓库。 私有仓库我们永远读不到，这不是故障，是设计。

GET /repos/expressj/express → 404 Not Found
message: "Not Found"

病例 C · 网络失败 NETWORK ERROR

请求没有发出去

FAILED TO FETCH

浏览器在拿到第一个字节之前就断了。常见原因：断网、 代理或 VPN 把 api.github.com 拦了、或者你在的公司网络不允许访问 GitHub。

TypeError: Failed to fetch
已接收 0 bytes · 耗时 0ms · 未进入 DNS 解析
测一下 GitHub 通不通
共同规则：错误必须说清三件事——出了什么事、为什么、现在能做什么。 永远不显示裸的 "Error" 或 "出错了"。技术信息用等宽字体照原样贴出，让人能复制去搜。

# Code ICU · 设计说明（design-spec）

> 设计：颜好看 ｜ 版本 v1.0 ｜ 面向 Phase 3 前端实现
> 三轴刻度：`DESIGN_VARIANCE = 6` / `MOTION_INTENSITY = 5` / `VISUAL_DENSITY = 6`
> 寄存器：**Product**（设计服务产品），但首屏带 Brand 级记忆点

---

## 1. 设计方向

**一句话**：把 GitHub 仓库当成病人，界面做成一张真的急诊病历 —— 暖白纸、等宽数字、虚线表格、红色圆章，唯一的彩色光源是那块深色监护屏。

三条不可让渡的决定：

1. **纸不是装饰，是信息结构**。表格线、虚线分隔、等宽读数、字段编号（`CY-01`、`字段 01`、`抓取于 10-26 10:04`）都在说"这是一份可以归档的医疗记录"。去掉这些，产品就变成一个普通的 GitHub 数据面板。
2. **绿色只属于"活着"**。主色（监护绿 `#067647`）不出现在主按钮上。主按钮是墨黑 —— 绿色一旦被用来做 CTA，就变成了"品牌色"，它的语义（生命体征正常）立刻贬值。所以：CTA 墨黑，绿色只给波形、评级条、通过态。
3. **红色只属于两处**：病危等级、印章。红色用多了就是噪音，一屏最多一个红色元素。

对标气质：Stripe Dashboard 的精确感 × 医院检验单的诚实感 × Linear 的克制。

## 2. 色板与取值理由

### 2.1 基底：暖白纸

| Token | Hex | 为什么是这个值 |
|---|---|---|
| `--bg` | `#FAFAF7` | 不是 `#FFF` 也不是奶油色 `#FDF6E3`。`#FAFAF7` 只在蓝通道少 3，肉眼读作"纸"而不是"黄纸"。纯白会让深色监护屏显得像贴上去的贴纸，暖白能托住它 |
| `--surface` | `#FFFFFF` | 卡片比纸更白一层 —— 就像打印出来的表格贴在病历本上 |
| `--surface-2` | `#F4F3ED` | 表单抬头条 / 表头底 |
| `--surface-inset` | `#EAE9E1` | 凹陷：评级条的轨道、头像底 |
| `--paper-rule` | `rgba(22,24,21,.028)` | 病历纸的横向格线，32px 一道。**opacity 必须这么低**：能感觉到纸，读不出线 |

> 为什么允许暖白基底：正常情况下"米色背景"是 AI 模板的默认懒惰选择。这里它是有理由的 —— 产品的整个隐喻是纸质病历。作为交换，页面上不允许出现任何其他"复古/温暖"的装饰（没有纹理图、没有复古衬线正文、没有做旧边框）。

### 2.2 前景四级（不是八级）

| Token | Hex | 对比度（对 `--bg`） | 用途 |
|---|---|---|---|
| `--fg` | `#161815` | **17.08:1** | 主文本。不是 `#000`：带一点绿调的近黑，和监护绿同源 |
| `--fg-2` | `#2E332E` | **12.33:1** | 次强文本、诊断句、建议正文 |
| `--muted` | `#5C635B` | **5.92:1** | 副文本、说明 |
| `--meta` | `#6A7066` | **4.87:1** | 等宽小标签、字段名、时间戳 |

> `--meta` 从初稿的 `#838A80`（3.40:1，不达标）改成 `#6A7066`。代价是它和 `--muted` 视觉上更接近了 —— 所以层级不靠颜色单打独斗，靠 **字号 + 字距 + 全大写** 三重区分（meta 永远是 10–12px + `0.12em` 字距的 mono 标签，muted 是 13–17px 的正常文本）。

### 2.3 主色：监护绿

| Token | Hex | 对比度 | 用途 |
|---|---|---|---|
| `--accent` | `#067647` | 5.44:1（纸面） | 焦点环、内联链接（"怎么算的"）、选中态 |
| `--accent-hover` | `#0B8F56` | — | hover |
| `--accent-soft` | `#E7F4EC` | — | 隐私声明底、激活步骤底 |
| `--monitor-trace` | `#3BF08C` | **12.28:1**（屏内） | 荧光磷绿波形。**只能在深色屏内用**，纸面上用会瞎 |

> 纸面上的绿必须够深（`#067647`），屏内的绿必须够亮（`#3BF08C`）。这不是两套主色，是同一个色相在两个亮度环境下的正确取值 —— 就像真的监护仪在纸上打印出来是深色，在屏幕上是荧光。

### 2.4 警报红与分诊五色

| Token | Hex | 对比度 | 语义 |
|---|---|---|---|
| `--alarm` | `#C1272D` | 5.59:1 | 病危等级、印章、NOW 标记 |
| `--alarm-deep` | `#9B1C1F` | 7.78:1 | 印章压色（叠加文字时用深的那个） |
| `--alarm-soft` | `#FBEDEC` | — | 病危红纸晕 |
| `--level-healthy` | `#067647` | 5.44:1 | 85–100 健康 |
| `--level-clinic` | `#2F6D8F` | 5.42:1 | 70–84 门诊随访 |
| `--level-ward` | `#A16207` | 4.71:1 | 50–69 住院观察 |
| `--level-icu` | `#C2410C` | 4.95:1 | 30–49 ICU |
| `--level-dead` | `#C1272D` | 5.59:1 | 0–29 临床死亡 |

> 五色是按**分诊台的真实逻辑**排的：绿（没事）→ 钢青（盯着）→ 琥珀（收进来）→ 焦橙（抢救）→ 红（宣告）。不是彩虹，是一根渐进的重症刻度尺。钢青而不是黄色放在第二档，是因为"门诊"是冷静的观察，不该比"住院"更刺眼。

**两套色阶分工（不要混用）**：

| 用在哪 | 用几档 | 阈值 |
|---|---|---|
| **六项单项体征**（报告页评级条、通知书体征条、对比图） | **三档** | `≥80 绿` / `30–79 橙` / `<30 红` |
| **总健康分、病危等级徽章、分诊标尺** | **五档** | 上表五个区间 |

理由：单项的"偏低"和总分濒死不该共用同一个红。express 的免疫 40.6 涂绿是宣传物料，涂红又过重——橙色才对。这条是全产品规则，不是某一张图的特例。

**三档的具体 Token 映射（写死，不要临场挑色）**：

| 三档区间 | 必须用 | Hex | 禁止用 |
|---|---|---|---|
| `≥ 80` 正常 | `--level-healthy` | `#067647` | — |
| `30 – 79` 偏低 | `--level-icu` | `#C2410C` | 禁用 `--level-clinic`（钢青，五档专用）<br>禁用 `--level-ward`（琥珀，五档专用） |
| `< 30` 危险 | `--level-dead` | `#C1272D` | — |

> 为什么单项的"橙"偏要用五档里叫 ICU 的那个焦橙：五档里 70–84 是钢青、50–69 是琥珀，两档的色相都指向"观察"而不是"该处理"。三档需要的是**一个**明确的警示橙，`#C2410C` 是这套色板里唯一够沉、能在暖白纸上压得住又不像红的橙。名字里带 ICU 只是历史包袱，语义以本表为准。
>
> 实现上不要复用「总分 → 五档」的那个 `classify()` 函数给单项上色——一个函数同时服务两套刻度，必然在 50–84 这一段出错。单项请单独写三档判定。

> **Canvas 导出卡同源**：`<canvas>` 画出来的病危通知书（§10）与报告页用的是同一条三档规则，禁止另立一套。request 实测：20.0 红、45.0 焦橙、70.0 焦橙；express 实测：80.0 绿、40.6 焦橙。凡是「单项分」出现在纸面上，颜色只由 `vitalTone(score)` 决定，与它所在的是网页还是 PNG 无关。


### 2.5 监护屏（页面里唯一的暗区）

| Token | Hex | 对比度（对屏底） |
|---|---|---|
| `--monitor-bg` | `#0E1613` | — （深绿黑，不是 `#000`） |
| `--monitor-grid` | `#1E2B25` | 细网格 24px |
| `--monitor-grid-2` | `#2A3A32` | 粗网格 120px |
| `--monitor-trace` | `#3BF08C` | 12.28:1 |
| `--monitor-text` | `#C8E6D6` | 13.78:1 |
| `--monitor-muted` | `#6E8C7C` | 4.99:1 |
| `--monitor-alarm` | `#FF6B5E` | 6.58:1 |

> 一块深色屏嵌在暖白纸里，这是全站最强的对比，也是唯一的"发光"区域。它承担了 80% 的记忆点，所以其他所有地方都必须安静。

### 2.6 主按钮：墨黑而非绿

| Token | Hex | 对比度 |
|---|---|---|
| `--action` | `#161815` | —（与 `--fg` 同值，语义不同） |
| `--action-on` | `#FAFAF7` | 17.08:1 |
| `--action-hover` | `#2E332E` | — |

> 理由见第 1 节第 2 条。副作用：黑按钮在纸面上像"铅字压印"，比绿色按钮更像公文。

## 3. 字体阶梯

### 3.1 三个字族

```css
--font-display: "Archivo", "PingFang SC", "Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei", system-ui, sans-serif;
--font-body:    同 display;
--font-mono:    "Martian Mono", "SF Mono", "JetBrains Mono", ui-monospace, Menlo, Consolas, monospace;
--font-serif-alt: "Songti SC", "Source Han Serif SC", "Noto Serif SC", serif;  /* 仅病危通知书标题 */
```

**为什么中文走系统字体栈而不是 webfont**：思源黑 / Noto Sans SC 的完整字重子集动辄 3–6MB，而本项目是**零构建的静态页**，还要保证弱网可用。中文用 PingFang SC（Mac/iOS）、Microsoft YaHei（Windows）—— 这两个是目标用户在用的系统里最好的中文黑体，零加载成本。

**为什么拉丁与数字要单独上 webfont**：

- `Archivo`（400/500/600）—— 略带方正感的工业无衬线，撑得住 `CODE ICU` 的字距与病危通知书的红头。它不像 Inter 那样被用烂，也不像 Space Grotesk 那样一开口就在喊"我是创业公司"。
- `Martian Mono`（400/500/700）—— 数字和仓库名用它。这是一款**窄体等宽**，字形高、通道窄，160px 的健康分放上去仍然像仪表读数而不是海报标题。这是本设计最重要的一个字体决定：**所有数字都是测量值，测量值必须长得像仪器**。

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Archivo:wght@400;500;600;700&family=Martian+Mono:wght@400;500;700&display=swap" rel="stylesheet">
```

### 3.2 阶梯（10 级，无中间值）

| Token | 移动 | ≥768 | 行高 | 用途 |
|---|---|---|---|---|
| `--text-2xs` | 10 | 10 | 1.2 | 表单字段名、评级权重、印章编号 |
| `--text-xs` | 12 | 12 | 1.5 | 辅助说明、时间戳 |
| `--text-sm` | 13 | 13 | 1.55 | 副文本、表格单元 |
| `--text-base` | 15 | 15 | 1.65 | 正文（诊断句、建议正文） |
| `--text-md` | 17 | 17 | 1.55 | 健康分结语、错误标题 |
| `--text-lg` | 20 | 20 | 1.4 | 仓库名、区块标题、单块数值 |
| `--text-xl` | 24 | 24 | 1.3 | 页面级标题（体检中 / 异常态） |
| `--text-2xl` | 30 | 30 | 1.2 | 异常态标题（桌面） |
| `--text-3xl` | 38 | 38 | 1.12 | 首页 H1（移动） |
| `--text-4xl` | 48 | **56** | 1.05 | 首页 H1（桌面） |
| `--text-5xl` | 64 | **88** | 1.0 | 健康分数字 |

> 中文正文 15px 而不是 16px：PingFang SC 的字面比拉丁大，16px 在 390px 宽度下每行只有 21 字，太挤。15px + 1.65 行高是中文移动端长文的舒适点。

### 3.3 字重三级

| 级别 | 值 | 用途 |
|---|---|---|
| Read | 400 | 正文、说明 |
| Emphasize | 510 | 小标题、按钮、表格值、诊断句强调 |
| Announce | 590 | 区块大标题、首页 H1 |

> 不用 700 做标题（除了 `CODE ICU` 字标和健康分数字）。590 在中文里能拿到 Semibold 的字面密度又不显得黑。

### 3.4 字距规则

| 场景 | 值 |
|---|---|
| 中文标题 | `-0.012em` ~ `-0.022em` |
| 中文正文 | `0` |
| 拉丁全大写标签（`HEART RATE`、`PATIENTS`） | `0.12em` |
| 拉丁大标题（`CODE ICU` 字标） | `0.16em` |
| 等宽数字 | `0`（tabular-nums，保证纵向对齐） |
| 病危通知书标题（宋体） | `20px`（≈0.33em，公文标题必须"散"） |

## 4. 间距、圆角、阴影

### 4.1 间距：4px 基准，只用 8 个值

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64 / 80`

- 区块垂直节奏：移动 `32px`，桌面 `56px`
- 卡片内边距：移动 `16px`，桌面 `20px`
- 表单行间距：`12px`
- 表格单元内边距：`10px 20px`
- 触摸最小尺寸：`44 × 44px`（`--touch-min`）

### 4.2 圆角：2 / 3 / 4 / 6px，没有更大的

| Token | 值 | 用途 |
|---|---|---|
| `--radius-xs` | 2px | 徽章、chip、评级条块 |
| `--radius-sm` | 3px | 按钮、输入框、图标容器 |
| `--radius-md` | 4px | 卡片、表单块、监护屏 |
| `--radius-lg` | 6px | 极少用（模态） |
| `--radius-full` | 9999px | 只给头像 / 圆点 |

> **这是抗 AI 味最关键的一个决定**。纸质表单的角是切的，不是圆的。任何 ≥ 8px 的卡片圆角都会立刻让页面变回一个 SaaS 面板。

### 4.3 阴影：几乎不用

| Token | 值 | 用途 |
|---|---|---|
| `--elev-flat` | `none` | 默认。所有卡片只用 1px 边框 |
| `--elev-paper` | `0 1px 0 rgba(22,24,21,.04), 0 2px 6px -3px rgba(22,24,21,.10)` | hover 抬升 |
| `--elev-lift` | `0 1px 0 rgba(22,24,21,.05), 0 8px 12px -8px rgba(22,24,21,.18)` | 浮层 |
| `--elev-poster` | `0 2px 0 …, 0 24px 60px -28px …` | **仅 1080×1440 分享卡**（该元素无边框，所以不构成"幽灵卡片"） |

> 带 1px 边框的元素绝不同时挂模糊 ≥16px 的阴影（幽灵卡片）。日常卡片 = 边框，不发光。

### 4.4 明暗层级不靠阴影，靠"纸的层数"

`--bg`（桌面）→ `--surface`（白纸）→ `--surface-2`（抬头条）→ `--surface-inset`（凹陷）。
深色屏是完全独立的一层，不参与这个阶梯。

## 5. 组件清单与状态矩阵

| 组件 | 变体 | 必须覆盖的状态 | 落点 |
|---|---|---|---|
| Button | primary（墨黑填）/ ghost（透明+1px 边）/ danger | default · hover · focus-visible · active · disabled(`opacity .45`) · loading | 首页、报告底、异常态、体检中 |
| Input | 前缀 `github.com/` + 仓库名 | default · focus-within（accent 边 + `0 0 0 3px accent-soft`）· error · disabled · filled | 首页 |
| Card / Sheet | 带抬头条 / 不带 | default · hover（仅可点击的） | 全站 |
| Chip | 5 个等级色 × sm/lg | default only | 病例行、报告分数、体征状态 |
| 评级条 | 5 段块 | 0–5 段填充 | 报告六项体征 |
| 分诊标尺 | 5 段（按分值宽度加权 20/25/20/20/16） | 当前档实心，其余 `opacity .16` | 报告分数卡、通知书 |
| 监护屏 | 静态（报告）/ 滚动（体检中） | idle · scanning | 报告、体检中 |
| 详情折叠 | `<details>` | closed · open | 六项体征说明、每项"怎么算的" |
| 步骤行 | done / active / todo | 3 态 | 体检中 |
| 异常卡 | 404 / 403 / network | 3 变体 | 异常态 |
| 印章 | 红章 | 静态（−9° / `opacity .9` / `multiply`） | 通知书 |
| Toast | 复制成功等 | 进出 220ms | 报告 |

**按钮尺寸**：高 44px（移动全宽 / 桌面自适应），内边距 `0 18px`，字号 15px，字重 510，圆角 3px。
**输入框**：高 44px，背景 `--bg`（比卡片略暗，形成"填写区"），聚焦时边框变 accent + 3px 外环。

**"阶段感"来自三件事**：① 每一步显示真实的 API 路径与返回（200 · 118ms / 96 次）；② 步骤之间有明确的 done → active → todo 迁移；③ 波形的滚动速度与"扫描"标签说明系统在持续工作。**没有转圈。**

### 6.3 report · 体检报告（`mockup-report.html`）

长页，顺序固定：

1. **患者档案**（`PATIENT FILE`）—— 头像 52/64px + `owner` 小字 + `repo` 20/24px 等宽 + 英文描述 + 6 个元数据格（STARS / FORKS / OPEN ISSUES / LANGUAGE / LICENSE / LAST COMMIT），移动 2 列、桌面 3 列
2. **健康分** —— `87`（64px/88px，Martian Mono 700，墨黑）+ `/100` + 等级徽章 + 一句诊断结语（17/20px）+ **分诊标尺**（五段按区间跨度 30/20/20/15/16 加权，当前档实心）+ **预后推演**（虚线上方 30px 等宽天数，下方一行 10px 公式小字，见 §9.5）
3. **监护屏** —— 12 个月提交画成 12 个心搏，深色屏、24/120px 双层网格、峰值标注 `14`、右缘红色虚线 NOW、`LIVE` 呼吸点；屏下三行等宽图注（峰值 / 谷值 / 波动比）
4. **六项体征** —— 单卡内 6 个 `divide-y` 行，每行：32px 图标框 + 名称/英文名 + 右对齐实测值 + 5 段评级条 + 状态点/状态词/评分/权重 + 一句人话诊断 + `<details>`「怎么算的」（原始数据 / 口径 / 公式 / 加成或惩罚 / 结果，四到五行）
5. **病史** —— 竖向虚线时间轴，方形节点（最新一个是实心绿），倒序：最近提交 → 最近发版 → 近 12 月工作量分布 → 建档，每条附一句解读
6. **治疗建议** —— 3 条，`P0/P1/P2` 等宽方框优先级标记 + 具体动作 + 依据（引用前面算出来的数字，如"130 条超过 90 天没人动，占了 51.4%"）。**健康仓库不硬凑 P0**：没有病危项就从 P1 起排，副标题写「3 条 · 无需住院」
7. **操作** —— `导出病危通知书`（墨黑主按钮）/ `重新体检` / `复制结论`

> 六项体征**不拆成六张卡**。一天张表格里的六行才像检验报告，六张圆角卡片就是六个 dashboard widget。

### 6.5 error · 异常态（`mockup-error.html`）

同一个组件三种参数，**每种都要说清三件事：出了什么事 / 为什么 / 现在能做什么**。

| 场景 | 标题 | 技术信息（等宽，可复制） | 下一步 |

## 9. 评分模型（前端必须照这个实现，否则示例数据对不上）

> **唯一依据是 `docs/SPEC.md` §6。** 本节只做"设计稿如何呈现"的转写，公式本身不得改动。任何分数都必须能由真实 API 返回的字段确定性推导，同一仓库同一时刻两次计算结果完全一致。

### 9.1 六项分项评分（SPEC §6 原式）

| 体征 | 取什么数 | 公式（照抄） | express 实测 |
|---|---|---|---|
| 心跳 heartbeat | `repo.pushed_at` | `d≤7 → 100`；`d≤30 → 100−(d−7)/23×10`；`d≤90 → 90−(d−30)/60×15`；`d≤180 → 75−(d−90)/90×20`；`d≤365 → 55−(d−180)/185×25`；`d>365 → max(0, 30−(d−365)/365×30)`；`archived → 0` | d = 2 → **100.0** |
| 呼吸 breathing | `commits?since=12月前` | `base = clamp(c/120×100, 0, 100)`；`trend`：`last6/prev6 ≥1.3 → +10`，`0.8–1.3 → 0`，`0.5–0.8 → −8`，`<0.5 → −15`（prev6 = 0 时：last6>0 → +10，否则 −10）；`score = clamp(base + trend)` | c = 96 → base 80.0，trend 46/50 = 0.92 → 0 → **80.0** |
| 单人依赖度 busFactor | 近 12 月 commits 的作者分布 | `authors = author.login 去重（排除 [bot]）`；`total === 0 → 20`；否则 `score = clamp(100 − maxShare×90 + (authors≥8 ? 8 : authors≥4 ? 4 : 0))` | 43 位作者，maxShare 11.9% → 100 − 10.71 + 8 = **97.3** |
| 代谢 metabolism | `releases?per_page=10` | 无任何 release → 45；否则按最近一次 `d`：`≤30 → 100`、`≤90 → 85`、`≤180 → 70`、`≤365 → 50`、`≤730 → 30`、`else 15`；`score = clamp(base + min(10, 近12月发版数×2))` | d = 16 → 100，加成 +10 → clamp = **100.0** |
| 免疫 immunity | `issues?state=open`（**必须过滤 `pull_request` 字段**） | `open === 0 → 100`；否则 `base = 100 − stale/open×100`（stale = `updated_at` 超 90 天）；`backlogPenalty`：`>500 → −15`、`>200 → −8`、`>50 → −3`；`score = clamp(base + penalty)` | 253 条中 130 条陈旧 = 51.4% → 48.6 − 8 = **40.6** |
| 遗嘱 legacy | `readme` + `license` | `license ? 40 : 0`；`readme ? 15 : 0`；正文字数 >1500 `+10`；含安装段 `+10`；含使用段 `+10`；含许可段 `+10`；含状态徽章 `+5`；`archived → −100`；`clamp(sum)` | 七项全在 = **100.0** |

**关键认知纠偏（第一版设计稿在这里错得最狠，必须记住）：**

- 心跳**不是**"每月平均提交数"，是"距最后一次提交多久"。提交密度归呼吸。
- 代谢**不是** issue 新开/关闭之差，是**发版节奏**。issue 积压归免疫。
- 免疫**不是** "CI / 测试目录 / SECURITY.md 在不在位"，是**僵尸 issue 占比 + 积压惩罚**。第一版那套"六项防护"在本产品里没有数据来源（要读 `.github/workflows` 目录，不在 5 次请求预算内）。
- 依赖度**不用 lifetime contributors**，用近 12 个月作者分布——否则二十年老项目永远显得"依赖创始人"，而近一年的分布才是当下的真实风险。

### 9.2 加权与分诊

```
weights = { heartbeat: .25, breathing: .20, busFactor: .20, metabolism: .10, immunity: .15, legacy: .10 }
health  = round(Σ score_i × w_i)

express = round(100.0×.25 + 80.0×.20 + 97.3×.20 + 100.0×.10 + 40.6×.15 + 100.0×.10)
        = round(25.00 + 16.00 + 19.46 + 10.00 + 6.09 + 10.00)
        = round(86.55) = 87
```

权重理由：呼吸给到 20%，因为**提交频率的衰减是整个模型里最好的早期预警信号**——一个项目往往先"少提交"，再"不提交"，最后才"不发版"。依赖度 20% 回答"这个人走了会不会停摆"。代谢只给 10%，因为发版可以完全由 CI 代劳，它证明流程还通，不证明代码还活着。

| 分数 | 等级 | 色 Token | 报告页文案基调 |
|---|---|---|---|
| 85–100 | 健康 | `--level-healthy` | 各项指标平稳，可放心使用 |
| 70–84 | 门诊随访 | `--level-clinic` | 存在需要关注的老化信号 |
| 50–69 | 住院观察 | `--level-ward` | 多项指标恶化，接手需评估成本 |
| 30–49 | ICU | `--level-icu` | 危重，除维护外不建议新接入 |
| 0–29 | 临床死亡 | `--level-dead` | 已无生命体征，仅作史料 |

分诊标尺的分段比例按区间跨度取 `30 / 20 / 20 / 15 / 16`（对应 0–29 / 30–49 / 50–69 / 70–84 / 85–100），不是等分——等分会把"临床死亡"这段压得太窄，读不出严重性。

### 9.4 心电图波形生成算法

12 个月的提交数画成 12 个心搏。**这一条是全页的视觉核心，务必按算法生成，不要用现成折线图。**

```js
// viewBox 720 × 208；x0 = 8；beatWidth = 704 / 12 = 58.667；baseY = 148
// maxAmp = 100；maxVal = max(data)  →  峰值那一个月正好顶到 y = 48
function beatPath(x, A, base) {
  // A = 该月提交数 / maxVal × maxAmp
  return [
    `Q${x+4} ${base-A*0.13} ${x+8} ${base}`,      // P 波
    `L${x+13} ${base}`,
    `L${x+17.5} ${base+A*0.16}`,                  // Q
    `L${x+22.5} ${base-A}`,                       // R（主峰）
    `L${x+27.5} ${base+A*0.30}`,                  // S
    `L${x+32} ${base}`,
    `L${x+36} ${base}`,
    `Q${x+40} ${base-A*0.26} ${x+45} ${base}`,    // T 波
    `L${x+beatWidth} ${base}`,
  ];
}
```

- 某个月提交数 = 0 → **不画心搏，直接拉平到下一拍**。整年无提交 = 一条直线 = 临床死亡的视觉表达，这是本产品最该做对的细节。
- 深色屏网格：细 24px（`--monitor-grid`）+ 粗 120px（`--monitor-grid-2`），用 SVG `<pattern>` 而不是 CSS 渐变，保证跟波形一起缩放。
- 峰值那一个月标注提交数（`14`），字体 10px 等宽、`--monitor-trace`。
- 右缘 NOW 虚线：`stroke-dasharray: 3 4`，`--monitor-alarm`，`opacity .55`。

### 9.5 寿命推演（报告页必须出现，且必须带公式小字）

```
decay         = 1 / (1 + d(repo.pushed_at) / 180)
remainingDays = clamp( round(health / 100 * 365 * decay), 3, 3650 )
```

| 仓库 | 健康分 | 停更 | decay | 推演剩余 |
|---|---|---|---|---|
| `expressjs/express` | 87 | 2 天 | 0.989 | **314 天** |
| `moment/moment` | 69 | 17 天 | 0.914 | **230 天** |
| `request/request` | 16 | 803 天 | 0.183 | **11 天** |

设计落位：健康分卡片内、分诊标尺下方，用一条虚线与标尺分隔（`.prognosis`），左侧 `PROGNOSIS` 等宽小标签 + 30px 等宽数字 + "天"，下方一行 10px 小字：

> 推演公式：`健康分/100 × 365 × 1/(1+停更天数/180)`，基于 6 项公开指标的确定性计算，不是预言。

**"不是预言"这四个字不能删。** 数字越小越吓人，越吓人越要说清它是算出来的、不是算命——这是这个产品可信度的地基。

### 10.3 印章（第 49 步，最后画）

```js
// 印章外框左上角 (606,1042)，边长 180px → 章心 (696,1132)
// 内部一律沿用 210×210 的局部坐标，靠 scale(180/210 ≈ 0.857) 整体缩小
// 坐标由 mockup-notice.html 的 .stampbox 归一化量取，不是目测：
//   getBoundingClientRect → x=593, y=1029, w=206, h=206（206 = 180 × (cos9° + sin9°) 的旋转外接框）
//   cx = 593 + 206/2 = 696，cy = 1029 + 206/2 = 1132，与 left+width/2 = 606+90 一致
// 位置理由：左边界 606 不压「备注」正文（其右边界 596）；右边界 786 不压落款文字（其左边界约 834），
// 中间留 48px 余量。注意 786 是**右边界**，不是章心 —— 章心比它小 90px。
ctx.save();
ctx.globalCompositeOperation = 'multiply';   // 模拟印泥压在铅字上
ctx.globalAlpha = 0.9;
ctx.translate(696, 1132);
ctx.rotate(-9 * Math.PI / 180);
ctx.scale(180 / 210, 180 / 210);
ctx.translate(-105, -105);
ctx.strokeStyle = ctx.fillStyle = '#C1272D';

// 外圈
ctx.lineWidth = 6; ctx.beginPath(); ctx.arc(105,105,99,0,Math.PI*2); ctx.stroke();
// 内圈
ctx.lineWidth = 1.6; ctx.beginPath(); ctx.arc(105,105,58,0,Math.PI*2); ctx.stroke();

// 五角星（实心，r=42 / 内接 r=16.8）
ctx.beginPath();
const P = [[105,63],[114.87,91.41],[144.95,92.02],[120.98,110.19],[129.69,138.97],
           [105,121.8],[80.31,138.97],[89.02,110.19],[65.05,92.02],[95.13,91.41]];
P.forEach(([x,y],i)=> i ? ctx.lineTo(x,y) : ctx.moveTo(x,y));
ctx.closePath(); ctx.fill();

/* ------------------------------------------------------------------ *
 * 弧形文字（Canvas 无 textPath，逐字符绕圆）
 *
 * 角度约定 —— 唯一事实源，与 HTML 版 <textPath> 逐字对齐：
 *   deg = 0 指向圆心**正上方**，顺时针为正（不是数学坐标系，别用 cos/sin 硬套）
 *   project(deg, r) = [CX + sin(deg)·r,  CY − cos(deg)·r]
 *   上弧：centerDeg =   0，字序沿 deg 递增，每字旋转 deg        （字头朝外，正向可读）
 *   下弧：centerDeg = 180，字序沿 deg 递减，每字旋转 deg − 180  （字头朝圆心，正向可读）
 *
 * 反例（旧版文档写错过，别再用）：拿 -90 当"正上方"，再套 cos/sin + rotate(a + π/2)。
 * 那套写法会把字排到章左缘、每个字自转 90°，下弧再翻 180° 整个倒过来。
 * ------------------------------------------------------------------ */
const CX = 105, CY = 105;
const project = (deg, r) => [CX + Math.sin(deg * Math.PI / 180) * r,
                             CY - Math.cos(deg * Math.PI / 180) * r];

function arcText(text, radius, centerDeg, fontSize, weight, font, spacing, inward = false) {
  ctx.font = `${weight} ${fontSize}px ${font}`;
  ctx.textAlign = 'center';
  ctx.textBaseline = 'middle';
  const chars = [...text];
  const step = 360 / (Math.PI * 2 * radius) * (fontSize + spacing); // 每字占的度数
  chars.forEach((ch, i) => {
    const offset = (i - (chars.length - 1) / 2) * step;
    const deg = inward ? centerDeg - offset : centerDeg + offset;
    const [x, y] = project(deg, radius);
    ctx.save();
    ctx.translate(x, y);
    ctx.rotate((inward ? deg - 180 : deg) * Math.PI / 180);
    ctx.fillText(ch, 0, 0);
    ctx.restore();
  });
}
// 字体与字重照抄 mockup-notice.html 的 <textPath>：--font-display / 上弧 600 / 下弧 500
const F_DISP = '"Archivo", "PingFang SC", "Noto Sans SC", sans-serif';
// 上弧：圆心 0° 为正上方，半径 76，5 字跨 ±46.7°
arcText('代码急诊科', 76, 0, 25, 600, F_DISP, 6);
// 下弧：圆心 180° 为正下方，半径 80，5 字跨 ±25.8°，字头朝圆心
arcText('诊断专用章', 80, 180, 15, 500, F_DISP, 3, true);

ctx.restore();   // 恢复 multiply / alpha / transform
```

> 上面这段是 **HTML 版印章的 Canvas 等价实现**。HTML 版用的是 `<textPath>`（见 `mockup-notice.html`），Canvas 没有 textPath，所以逐字旋转。两者视觉差的唯一来源是字符间距的取整 —— 验收时以 HTML 版为准，Canvas 版允许 ±1px。

## 11. 交给前端的 9 条注意事项

1. **不要给卡片加圆角，不要加阴影。** 边框 + 4px 圆角是这套设计的骨架，改一处全盘崩。
2. **所有数字必须 `font-family: var(--font-mono); font-variant-numeric: tabular-nums`**。中文数字（"六项""两百万"）除外 —— 那是文字，不是读数。
3. **主按钮不要改成绿色。** 绿色属于"生命体征"，不属于"行动"。
4. **每屏 accent 绿的使用 ≤ 2 处**（不含体征状态色）。超了就说明你把绿色当装饰了。
5. **波形不要用现成图表库**。按 9.4 节算法手绘 SVG/Canvas。折线图一出，整个产品就变成 BI 面板。
6. **0 提交的月份必须是平的**。这是产品情绪的落点。
7. **错误态不允许说"出错了"**。三段式：出了什么事 / 为什么 / 现在能做什么。
8. **`prefers-reduced-motion` 必须真的生效**（`design-tokens.css` 底部已全局处理，别被后来的 `!important` 覆盖）。
9. **权重和公式一个字都不要自创**。六项权重固定 `.25/.20/.20/.10/.15/.10`，实现完后拿 `expressjs/express` 跑一遍，健康分必须落在 87±2。如果你算出来是 64 或 90，说明你用了别的公式——不是数据变了，是公式错了。

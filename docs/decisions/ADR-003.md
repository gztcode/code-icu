# ADR-003: 发行形态选 PWA + 三平台压缩包，不用 Electron

## Status
Accepted (2026-10-26)

## Background
作品需要一个「发给别人就能直接跑」的形态，覆盖 Windows / macOS / Linux 三个平台。可选路径有四类：在线托管站、浏览器扩展、Electron 桌面应用、含本地服务器的压缩包。

## Decision
发行形态定为**四层并行**，按安装成本从低到高：

1. **在线版**（GitHub Pages）—— 零安装，评委点开即用
2. **PWA** —— 可安装为独立窗口的桌面应用，断网可开
3. **三平台压缩包** —— 解压双击启动脚本即用，含零依赖本地服务器
4. **源码包** —— 完整源码，算法可复核

**不使用 Electron。**

## Consequences

**正面**
- 运行时零依赖这条主线没被破坏：压缩包里的 `server.mjs` / `serve.py` 都是零依赖实现，不需要 Node 运行时之外的任何东西
- 体积可控：桌面包约 158 KB，源码包 336 KB；Electron 打包后是 80–150 MB 量级
- 三平台共用同一份产物（`src/`），打包只是换个启动脚本 + 说明文件，不存在三套代码
- PWA 让「装成 App」这件事零成本：不需要签名、不需要公证、不需要安装包
- 离线可用由 Service Worker 保证，实测断网后仍能打开首页

**负面**
- 桌面包不是真正的原生应用：没有系统托盘、没有原生菜单栏、窗口由浏览器渲染
- 启动脚本依赖机器上有 Node.js 或 Python 3 任一（Windows 用户装 Python 的成本高于装 Electron 应用的接受度）
- 无法做「双击图标就装到系统」的一键安装体验（PWA 的安装是浏览器内的两步操作）
- 若未来要上架应用商店 / 做原生集成，仍需补 Electron 或 Tauri

**关于 Electron 的具体否决理由**
- 引入它意味着 `package.json` 从「零运行时依赖」变成「几百 MB 的 devDependencies」，与 ADR-001 的核心主张冲突
- 跨平台打包需要 `electron-builder` 之类的构建链，打包耗时长且容易在不同平台上偶发失败
- 本项目的全部价值在算法与视觉，不在「有没有一个 .app 图标」
- Electron 应用的体积与启动时间，对一个「打开就能用」的演示型作品是净负担

### 关键技术决策：不用 `python3 -m http.server`

压缩包原本让启动脚本在缺 Node.js 时回退到 `python3 -m http.server`。实测这是**错的**：

| 服务器 | 连续 12 次加载 · 渲染失败 | 请求失败 |
|---|---|---|
| `python3 -m http.server`（监听队列 5） | **6** | 6 |
| `serve.py`（队列 128 + 线程） | **0** | 0 |

原因：`http.server` 继承 `socketserver.TCPServer`，`request_queue_size = 5`；本页一进来要并行拉 30+ 个 ES Module，队列溢出会让内核 RST 掉排在后面的连接，浏览器表现为「随机一个模块 `ERR_CONNECTION_RESET`」，页面白屏且时好时坏。

这个坑在项目里已经踩过一次（`tests/serve.mjs` 的注释里记着），差点又踩一次。修法是自带 `serve.py`，把队列放大到 128 并改用线程模型。README 里原本推荐 `python3 -m http.server` 的写法也已一并删掉。
